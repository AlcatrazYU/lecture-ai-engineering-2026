## 宿題

- 取り組んだレベル：実装
- やったこと：`app/tools.py` に `save_learning_log(lecture: int, content: str) -> str` を追加し、学習記録を `learning_log/` に保存できるようにした。ファイル名は `lec03-20261107-025636.md` のように講義回と保存日時から生成し、同じ秒に同名ファイルが存在する場合は連番を付けて過去の記録を上書きしないようにした。`app/agent.py` ではこのツールを `requires_approval=True` で登録し、LLMが保存を要求したときに、実行前にツール名と引数を表示して利用者の承認を求める処理を追加した。
- 結果：`--list-tools` で4個のツールが表示された。承認プロンプトで `n` または `u` を入力した場合は保存が拒否され、`y` を入力した場合だけ `learning_log/lec03-20261107-025636.md` が作成された。保存されたファイルには「今日はAgent・ツールユース・ハーネスについて勉強しました。」という内容が入っていた。`uv run pytest -q` は14 passedで成功した。
- 気づき・疑問：`requires_approval=True` により、ファイル書き込みのような取り消しにくい操作をLLMの判断だけで実行せず、利用者の確認を挟めることが分かった。`n` や `u` など `y` 以外の入力を拒否として扱うことで、承認しない限り保存されない設計になっている。

## 工夫した点・難しかった点

課題では保存先を `learning_log/` と指定しているだけで、ファイル名の指定はない。最初はCopilotが実装を簡単にするための案として `latest.md` への保存を提案したが、それでは保存するたびに過去の記録が上書きされるため、今後の学習記録を残して再利用したいという実際の目的に合わせ、ファイル名を `lec03-20261107-025636.md` のように講義回と保存日時から作る設計にした。同じ秒に同名ファイルが存在する場合は連番を付け、過去の記録を上書きしないようにした。

難しかった点は、既存のPythonコードを手動で編集するときにインデントを正しく合わせることである。Pythonではインデントが見た目だけではなく、処理の階層や実行される範囲を決めるため、少しずれるだけでも構文エラーや意図しない動作につながる。提示されたコードの位置とインデントを確認しながら追加し、`py_compile`、実際の承認・拒否操作、保存ファイルの確認、`pytest` を順番に実行して動作を確かめた。初学者にとっては基本的な点だが、実際に手を動かすことで、Pythonではコードの内容だけでなく配置とインデントも重要だと分かった。
